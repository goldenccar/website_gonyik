# 港翼官网自动化质量审计

该工具使用 Node.js 原生能力实现，不引入额外测试框架或运行时依赖。它用于在本地或部署前快速发现数据链路、组件复用和性能方面的明显回归，但不替代浏览器端视觉验收与业务测试。

## 使用方式

```bash
# 构建后执行质量审计
npm run test:quality

# 完整发布检查：单元/烟雾测试、生产构建、质量审计
npm run test:release

# 已有构建产物时，仅执行静态审计
npm run audit:quality
```

## 检查内容

### 数据流向

- 识别前端 `api.get/post/put/delete` 与 `cachedGet` 调用。
- 识别 Express 路由及项目统一内容集合注册器生成的 CRUD 路由。
- 对 HTTP 方法和规范化路径进行匹配；前端调用找不到服务端路由时阻断发布。

动态运行时拼接的 URL 无法可靠地通过静态分析确认，仍应由烟雾测试或人工验证覆盖。

### 组件复用

- 检查 `src/**/components` 下未被任何模块引用的组件。
- 检查内容完全相同的重复组件。
- 两类问题均视为阻断项，避免旧组件和复制代码持续累积。

### 原生交互

- 提示使用 `div`、`span`、`li` 等非原生元素承载点击行为的位置。
- 该项只提示、不阻断，因为遮罩关闭、含嵌套操作按钮的可选择行等场景不能简单替换为 `<button>`。
- 每一项需结合键盘操作、ARIA 语义和 DOM 嵌套关系人工复核。

### 性能预算

- JavaScript 单文件 gzip 上限：120 KB。
- CSS 单文件 gzip 上限：90 KB。
- `public` 单个静态资源上限：750 KB。
- 超出任一预算即阻断发布；大型媒体应转为合理尺寸的 WebP/JPEG，或明确拆分与延迟加载。

## 设计原则

- 规则必须有明确的发布价值，避免为了“零告警”进行错误重构。
- 可以可靠判断的问题才阻断发布；需要语境判断的问题只生成复核提示。
- 优先复用浏览器、Express、Node.js 与 HTML 原生能力，不为简单检查增加长期依赖。
- 阈值集中在 `scripts/quality-audit.mjs` 中，后续可随真实流量和设备数据调整。

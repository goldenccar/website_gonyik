## 1. 产品定义

### 1.1 品牌定位

港翼科技（GONYIK）是无氟高性能面料与材料解决方案公司。官网面向品牌采购、产品开发、设计研发和专业机构，核心任务不是零售成交，而是：

1. 解释材料与工艺能力；
2. 让采购方快速找到合适的面料或应用方向；
3. 以可验证但不过度公开的方式建立可信度；
4. 引导用户通过联系页或微信小店继续沟通。

### 1.2 核心用户与任务

| 用户 | 首要任务 |
|---|---|
| 品牌采购/供应链 | 判断性能方向、供应能力、认证与合作可行性 |
| 产品经理/设计师 | 按使用场景筛选面料，理解系列差异，索取样品/TDS |
| 材料/研发人员 | 理解膜、纤维、复合与验证逻辑 |
| 终端用户/媒体 | 理解品牌定位、产品应用和保养方式 |
| 内容运营人员 | 在不改代码的前提下维护页面、语言、地区、导航和媒体 |

### 1.3 非目标

- 官网不提供零售支付、库存或订单能力；
- 不公开完整 TDS、测试原始报告或客户专属数据；
- 不展示未经授权的客户 Logo 或工商/股东关系；
- 不把合作方的认证泛化为港翼全部产品自动取得认证；
- 不用无证据的绝对化、医学或比较级主张替代测试依据。

## 3. 页面需求

### 3.1 全局 Header 与 Mega Menu

- 桌面 Header 覆盖在 Hero 上时使用透明/深色适配状态，滚动后使用稳定背景；
- 当前页面状态与 hover 状态必须能明确区分；
- Mega Menu 只展示一、二级导航，不写说明句；
- 面板宽度与内容量匹配，并与 Header 内容区右侧对齐；
- 展开/收起使用连续的高度、透明度和位移动画，不允许突变；
- 面板打开时点击页面任意非面板区域、按 Escape 或切换路由均应关闭；
- 地区选择器遵循相同关闭规则；
- 移动端使用可访问的按钮和折叠菜单；
- 导航文字、分组、排序和可见性由 CMS 维护。

### 3.2 首页

#### Hero

- 首屏横向全出血，纵向覆盖首个视口；
- 文案位于稳定的左侧阅读区；
- 当前建议文案：
  - 标签：`PFAS-FREE PERFORMANCE TEXTILES`
  - 标题：`以材料科技，构建无氟高性能面料`
  - 摘要：`港翼从膜、纤维与复合结构出发，协同制造与验证，开发面向真实应用的功能面料。`
- 保留“探索面料产品”“了解技术与材料”两个 CTA；
- 底部显示“下滑探索港翼科技”提示，位置相对视口底边固定；
- Header 与 Hero 的安全区必须适配桌面和移动端。

#### 后续内容

首页只做高密度摘要，不复制技术页正文：

1. 无氟技术体系与 RPO 材料平台摘要；
2. 膜、复合、供应链三项材料系统可视化；
3. 性能验证区，实验室图片支持最多 5 张、自动轮播与手动切换；
4. OTTER、RAYO、KAIS 三大面料平台；
5. 应用/装备入口；
6. 联系 CTA。

首页 CTA “查看全部系列”统一为“查看全部面料产品”。

### 3.3 面料产品页

- 三个系列纵向排列；
- 顶部选择器用于快速跳转到系列，滚动与激活状态双向同步；
- 每个系列每行两张 SKU 卡片，新增 SKU 自动换行；
- 卡片正面展示图片、型号、短描述、特征和简要性能；
- 卡片翻转后展示结构、材料、核心性能、适用方向与索取 TDS 入口；
- 多张卡片可同时翻开；点击翻开卡片任意位置可返回正面；
- 翻转使用真实 3D 透视、正反面背面隐藏，不得出现内容缩成左上角或尺寸跳变；
- 系列标题有轻量可点击提示，进入系列叙事页，文案使用“查看系列性能”而非“了解系列故事”；
- “新面料开发”CTA 位于系列内容之后，不能插入 SKU 与展开详情之间。

SKU 与系列是映射关系：删除/隐藏系列不删除 SKU。SKU 必须可重新映射。

### 3.4 系列叙事页

- OTTER、RAYO、KAIS 分别讲不同价值，不强行使用同一卖点；
- 页面需要把描述性价值与专业 SKU 分开；
- 页面末尾 CTA 返回 `/fabrics#series-{slug}` 并定位对应系列；
- 首页三大平台和面料页系列标题都可进入该页。

### 3.5 应用与装备页

- 一级分类：成衣、鞋履、配件等，可 CRUD、排序、隐藏；至少保留一个可见一级分类；
- 二级分类按一级分类独立配置，同样支持 CRUD、排序、隐藏；
- SKU/产品与分类只是映射关系，删除分类不删除产品；
- 某分类已有具体 SKU 时，不显示“新产品开发”卡；
- 空分类使用面向客户的简洁状态，不显示内部数据规则；
- 鞋履可暂为空；
- 产品可设置 `RPO Pro` 标识，表示使用 RPO 膜或纤维；未使用时不强制标记或包装为较低等级；
- 官网只展示，销售统一由 Footer 导流微信小店，不承诺商品级深链。

### 3.6 服务与资源

- 复用统一 Hero；
- 子选择器支持吸顶和毛玻璃效果，吸顶前后连续过渡；
- 材料保养和成衣保养可展示洗涤剂/防水喷雾等配套产品软文及关联成衣；
- 数字面料支持 CLO3D、Style3D 等工作流说明，但不能把“正在建立”“内部交付约束”等文字写在前台；
- 洗涤与保养页面使用编辑式内容排版，不使用通用模板卡片堆叠。

### 3.7 联系页

- 收集姓名、公司、联系方式、项目阶段、应用环境和需求说明；
- 不加入官网零售订单字段；
- 服务端校验、限流、蜜罐字段和邮件发送失败处理必须保留；
- 成功状态必须明确，不泄露内部收件地址或系统信息。

## 4. CMS

### 4.1 原则

- CMS 是内容事实源；前台不先渲染旧默认文字再替换 CMS 内容；
- 首次启动显示轻量加载状态，统一 bootstrap 完成后再渲染公共框架；
- 默认数据仅用于全新环境初始化和字段迁移；
- 页面框架配置置于 CMS 导航顶部，各模块按前台顺序排列；
- CMS 底部提供模块排序管理；
- CMS 左侧导航独立固定，不随右侧编辑内容滚动；
- CMS 提供“返回前台首页”按钮。

### 4.2 管理模块

- 页面框架：首页、导航、Footer、联系信息、社交媒体；
- 材料科技：页面标题、Hero、选择器文字、章节正文、媒体、市场可见性；
- 面料：系列、SKU、性能、标签、图片、排序、关联；
- 装备：一级/二级分类、产品、RPO 标识、映射与可见性；
- 服务与资源：页面、章节、图片、跳转；
- 市场与语言：地区、默认语言、翻译对象、内容可见性；
- 媒体库：查看当前已使用和未使用资源、下载原图，最多批量配置应有上限；
- 管理员：账号和密码维护。

### 4.3 多语言数据模型

一个可翻译字段对应一个文案对象：

```ts
type LocalizedText = Record<string, string>

interface LocalizedContent {
  title: LocalizedText
  description: LocalizedText
}
```

- 当前至少支持 `zh-CN`、`en`；结构可扩展 `zh-TW`、`ja`、`ko`；
- 地区配置决定默认语言；
- 翻译缺失的回退顺序由 CMS 配置，前台不得逐字段闪烁切换；
- 选择器短标签建议中文不超过 12 个汉字、英文不超过 28 个字符；CMS 校验并显示计数；
- 排版使用弹性宽度、自动换行和可控最小/最大宽度，不依赖固定文案长度。

### 4.4 内容可见性

内容实体支持：

```ts
interface MarketVisibility {
  visible?: boolean
  markets?: string[] // 空或缺省按全局策略处理
}
```

隐藏只影响对应市场的前台与公开 API，不删除实体。全局内容可在 `global` 市场维护。

## 5. 数据模型与流向

### 5.1 启动数据

公共框架通过单一 `/api/bootstrap` 获取：

- 站点配置；
- 导航；
- 首页配置；
- 面料系列摘要；
- Footer、联系、社交；
- 市场、当前市场、当前语言和翻译。

页面域数据使用聚合接口：

- `/api/fabrics/catalog`：页面、系列及各系列 SKU、能力标签；
- `/api/equipment/catalog`：页面、分类和产品；
- `/api/services/bootstrap`：服务页面及章节。

技术详情页和其他低频内容按路由加载。API 客户端只去重并发中的同一请求，不使用会导致旧内容闪现的长期内存缓存。

### 5.2 关系约束

- 系列 ↔ SKU：映射，不级联删除；
- 装备分类 ↔ 产品：映射，不级联删除；
- 技术导航 ↔ 技术页：路由引用，删除前必须检查引用；
- 媒体 ↔ 内容：资源引用，只有确认无引用后才允许清理；
- 市场 ↔ 内容：可见性映射，不复制实体。

### 5.3 迁移

`server/db.ts` 的初始化与迁移必须幂等：

- 只补缺失字段，不覆盖 CMS 已维护内容；
- 任何字段重命名先兼容旧字段，再迁移；
- 不把开发默认文案重新写入已有生产数据；
- 发布前用生产数据副本验证迁移。

## 6. 组件与实现

### 6.1 公共组件边界

优先复用：

- `Header` / Mega Menu / 地区选择器；
- `Footer`；
- 统一 Hero；
- 技术页选择器和 `TechnologyStory` 骨架；
- 媒体编辑/裁切组件；
- 面料 SKU 卡片与系列跳转；
- CTA、富文本解析器、响应式图片；
- 后台 `Modal`、表单字段、响应式管理列表。

页面特有动效保留为独立可测试组件，例如膜结构、膜防水、复合压合、供应链循环。

### 6.2 原生优先

- 导航使用 `<a>`/路由链接；
- 操作使用 `<button>`；
- 后台弹窗使用 `<dialog>`；
- 展开内容优先 `<details>/<summary>`，除非动画或状态同步有明确需求；
- 表单使用原生 label、input、select、textarea 与约束验证；
- 禁止用带 `onClick` 的 `div` 模拟按钮。

## 7. 视觉与交互规范

### 7.1 设计语言

- 视觉气质：材料科学、工业精度、克制而非炫技；
- 主色：海军蓝、石墨黑、雾白、冷灰；青色仅作状态和技术指示；
- 直角/极小圆角、细分隔线、真实材质和工业摄影；
- 允许全出血 Hero，正文回到统一内容宽度；
- 不使用无意义的 01/02/03 编号、装饰性网格或模板化图标卡；
- 图片底色必须与容器融合，阴影属于材质表现，不能被容器裁断。

### 7.2 字体与阅读

- 使用仓库自托管字体，不依赖第三方字体 CDN；
- 中文正文桌面建议 18–20px，行高 1.7–1.85；移动端 16–18px；
- 技术页控制每行 30–42 个汉字；
- 标题和正文不机械居中堆叠，使用偏移、留白与图文轻重建立层级；
- 英文大小写和术语保持一致，如 `RPO Material Platform`。

### 7.3 动效

- 动效用于解释水汽、雨滴、复合、循环等关系；
- 使用 transform/opacity，避免频繁布局；
- `prefers-reduced-motion` 下关闭循环和大位移；
- 卡片 hover 动画只在支持 hover 的设备启用；
- 吸顶选择器状态改变必须连续，不能切换 DOM 造成跳变。

### 7.4 响应式与无障碍

- 基准宽度：375、768、1024、1440；
- 键盘可操作 Header、Mega Menu、地区选择器、轮播和弹窗；
- 保持可见焦点；
- 文字对比度达到 WCAG AA；
- 图片有语义化 alt；装饰图 alt 为空；
- 原生对话框支持 Escape、焦点约束和背景不可交互。

## 8. 内容与证据规则

### 8.1 外部文案原则

- 写用户能获得什么，以及能力如何形成；
- 内部风控、数据建模、合作边界和“不可泛化”规则写在 CMS 提示和本文档，不写进前台；
- 技术主张必须与具体材料、SKU、测试条件或报告范围关联；
- “SGS、OEKO-TEX®、GRS、bluesign®”等标识只在授权且范围准确时展示；
- 高校名称、奖项、专利、认证和材料比较必须有可核验依据。

### 8.2 公开深度

- 前台可公开：代表性特征值、适用场景、结构逻辑、验证流程摘要；
- 定向提供：完整 TDS、原始测试报告、客户项目数据、详细工艺窗口；
- 测试页是能力说明，不是公开下载中心。

具体文案问题和建议见 `files/COMPETITIVE_AUDIT_2026-08.md`。

## 9. 性能

- 首屏公共数据只有一次 bootstrap 请求；
- 页面域数据使用聚合接口，避免列表后逐项请求；
- 图片按最大显示尺寸提供响应式版本，Hero 与关键技术图预加载，其余懒加载；
- 静态资源使用内容哈希和长期缓存；HTML no-store/no-cache；
- 上传资源设置合理缓存并避免同一图片重复存储；
- 动效资源需控制尺寸，960px 宽的展示图通常可覆盖当前 2× 展示需求；
- 发布前运行质量审计、单测、类型检查和构建。

## 10. 安全与可用性

- 生产必须使用 HTTPS；
- Helmet/安全响应头和生产 CSP 保持开启；
- 管理员密码 bcrypt 存储，JWT 密钥由环境变量提供且强度校验；
- 登录、联系和全局 API 分级限流；
- 只接受允许来源的写请求；
- JSON、表单和上传设置尺寸与 MIME 限制；
- 上传文件名随机化，不执行上传内容；
- 后台接口必须鉴权；
- 日志不记录密码、Token 或完整个人信息；
- 定期备份 `db.json` 和 uploads，恢复演练必须可执行；
- 大流量优先使用 CDN/WAF、Nginx 限流和静态缓存，不在应用内增加复杂自研防御。

详见 `files/SECURITY_AND_LOAD.md`。

## 11. 部署

### 11.1 正常发布

1. `npm run test:release`（或部署脚本复用同一源码指纹的已通过结果）；
2. 提交并推送 `main`；
3. 服务器只在 lockfile 变化时运行 `npm ci`；
4. 构建前端；
5. PM2 reload；

7. 检查生产首页和关键 API。

使用仓库部署脚本，凭据仅保存在本机未跟踪文件或 CI secret。不要在文档记录服务器 IP、root 密码或管理员默认密码。

### 11.2 回滚

- 程序回滚到上一个已验证 commit；
- 数据问题使用发布前备份恢复，禁止用 Git 覆盖生产 `db.json`；
